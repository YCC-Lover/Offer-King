## 下载与安装

### 我应该下载哪个文件？

可以[直接下载 Windows 2.3.0 候选试用包](https://github.com/YCC-Lover/Offer-King/releases/download/v2.3.0/Offer-King-Setup-2.3.0.exe)，也可以在 [2.3.0 发布页](https://github.com/YCC-Lover/Offer-King/releases/tag/v2.3.0) 的 **Assets** 中选择 `Offer-King-Setup-2.3.0.exe`。GitHub 的 `Source code` 压缩包不是应用安装包。安装前请看下方安全提醒并核对 [SHA-256](QUICKSTART.md#安装前先核对)。[历史 2.2.0 发布页](https://github.com/YCC-Lover/Offer-King/releases/tag/v2.2.0) 仍保留。

### 为什么标记为候选试用版？

2.3.0 在 GitHub 标记为 **Pre-release**，已有开发版与打包程序的自动化回归，但**真实干净 Windows 首装和覆盖安装尚未验收**，卸载也待测试。候选版不等于完整安装验收的正式版；愿意接受这个范围再下载，旧用户先手动导出备份。GitHub 的 Latest 可能仍指向其他版本，请使用这里的固定 2.3.0 链接。

### 下载后能直接使用吗？需要懂编程吗？

不需要懂编程，也不需要下载源码或安装开发工具。在支持的 Windows x64 电脑上安装成功后，即可新建投递、记录面试、填写薪酬、比较 Offer、做城市预算和备份；不配置 AI 也能使用这些核心功能。

第一次打开是自己的空白记录，不包含作者的求职资料或密钥。AI 是可选功能，使用时另行配置自己的 API Key，调用可能收费。当前安装包未签名，干净电脑上的首装仍未完整实测，不能保证每台电脑都安装成功。

### 下载一定要注册 GitHub 吗？

不需要。公开安装包和教程可以不登录 GitHub 下载、查看。提交 Issue、点 Star 或订阅更新才需要 GitHub 账号；App 本身没有注册或登录步骤。

### 支持哪些系统？

当前提供 Windows 10 / 11 x64 版本，应用最小窗口为 1100 × 700。尚无 macOS、Linux 或手机安装包；窄屏布局不等于手机系统支持。真实干净 Windows 首装、覆盖升级及物理多屏环境仍待进一步验证。

### 怎样切换英语、日语或韩语？会清空正在编辑的内容吗？

2.3.0 可在侧栏的语言选择器，或“设置与备份 → 显示与可读性 → 界面语言”中选择 **简体中文、English、日本語、한국어**。切换立即生效，无需重启，并记住本机选择；正在编辑的内容会保留。

公司名、岗位名、备注、人工阶段名与已有 AI 调研原文不会自动翻译。默认阶段只翻译显示，不改数据库中的名称。语言偏好不进入求职 JSON 备份，也不更换 AI 模型、密钥或收费同意。图文教程仍保留旧版中文截图；可通过页首四语入口阅读对应语言指南。旧 2.2.0 安装包仍为中文界面，需要下载 2.3.0 才能使用语言切换。

### Windows 提示“未知发布者”，怎么办？

2.3.0 候选试用包尚未签名，可能触发系统提示。请先核对下载来源和 [SHA-256](QUICKSTART.md#安装前先核对)，遵循系统安全建议。不要关闭杀毒软件、Defender 或 SmartScreen；持续拦截时停止安装并反馈。哈希一致不等于安装包具有数字签名或绝对安全。

### 有自动更新吗？升级会保留数据吗？

目前没有自动更新，请关注发布页。新版保留了原有数据身份，但真实安装器覆盖升级尚未完成验证，不能保证所有环境下均无问题。

更新前务必手动导出 JSON、关闭旧版、保留原安装位置，不要先清空数据。更新后检查公司、岗位、薪酬和配置；不要马上丢弃升级前的备份。

### 为什么部分文件名还是旧名称？

界面品牌是 Offer King。部分内部标识和文件名为兼容既有数据而保留，不意味着装错版本。请以“帮助与关于”中的版本和对应发布包为准，不要自行重命名或移动数据文件。

## 记录与保存

### 不配置 AI 能用吗？需要账号吗？

不需要应用账号，AI 也不是前置条件。你可以手动记录公司、岗位、薪酬，使用看板、PK、城市预算和备份。

核心管理功能不要求联网；但公司官网图标会访问公开网站，主动 AI 调研也会联网，所以不要把“本机保存”理解为“所有操作都绝不联网”。

### 我的记录会和朋友同步吗？

不会。当前是本机单人使用，没有云同步。朋友安装后使用自己的记录与 AI 密钥。给朋友分享发布页链接即可，不要分享自己的备份或整个数据目录。

### 改完资料，为什么下次打开不一样？

岗位、公司、薪酬等资料要明确点击保存。岗位详情的“保存全部更改”包含概览、公司和薪酬，不包含尚未添加的流程记录；流程要单独添加。AI 已预填到草稿的内容也需要核对保存，仍停留在建议预览中的内容不会因“保存全部更改”自动采纳。

PK 要点击“保存方案”，城市预算要点击“保存预算”。请留意页面的成功提示；出现保存错误时先保留输入，不要强制关闭应用。

### 意外关闭后，能找回未保存内容吗？

新建岗位、岗位资料（含薪酬）、公司资料和未添加的流程记录，会在停止输入约半秒后尝试在本机暂存。重启后可在首页查看“待恢复草稿”，恢复到表单后仍需核对并明确保存。

自 2.2.0 起也支持 **PK 与城市预算** 的恢复草稿，包括尚未保存过的新方案，2.3.0 继续保留。先预览再恢复到编辑表单，正式记录已更新或删除时会提示，不用旧草稿静默覆盖。恢复不等于保存，仍需点击“保存方案 / 保存预算”。

暂存最多 10 份、约 1 MiB，不是备份，也不保证恢复断电前最后半秒的输入。完整招聘原文不会在异常重启后恢复，但已采纳字段与有限证据摘录可以保留。已保存的方案会持久保留，并进入 JSON 备份。

### 提醒会在关闭应用后弹出吗？

当前待办是应用内提醒，不是系统后台通知。重要的面试时间建议同时记入你常用的日历。完成待办不会自动改变求职阶段。

### 七天之后或还没定时间的事项，在哪里看？

打开首页或侧栏的“全部待办”，选择“以后”或“待安排时间”。逾期、今天、未来七天也在同一列表，长列表可完整滚动。完成事项会写入流程记录并清除下一事项；调整时间请打开对应岗位详情。已归档、已拒绝、已结束岗位不进入待办，公司单独归档不影响仍活跃的岗位事项。

### 看板里的记录怎么少了？

先清空当前页搜索和筛选，查看是否已归档，再检查列内分页。岗位看板每列每页最多 25 条，风险看板每列每页最多 40 条；分页不会删除记录。每个页面的搜索只作用于该页面，并覆盖全部匹配记录，不局限于眼前一页。

### 撤销能恢复所有操作吗？

不能。看板阶段撤销 / 重做只保留本次运行最近 20 次阶段移动，重启后为空，不是通用历史恢复。输入框内的 `Ctrl+Z` 仍是文字撤销；阶段撤销也不会删除已有的流程记录。

## Offer、薪酬与城市预算

### “最终选择”会替我接受 Offer 吗？

不会。它只是你的个人标记，不会联系公司，也不会自动接受或拒绝任何 Offer。决策状态、决策截止、下一事项和求职阶段是不同信息，需要按实际情况维护。

### 为什么没有综合分，或者显示“待补充”？

系统不会把未知资料当作零分。请检查正权重指标是否齐全，自动金额指标的币种是否一致，以及城市预算是否完整、是否选对。多份预算需要明确选择；未确认的信息不应仅为了得到一个分数而随意填值。

### 保存过的 PK 分数为什么变了？

PK 保存的是方案、指标、评分、权重和备注等信息；薪酬与所选预算会使用最新正式资料重新计算。因此它不是锁定当时所有金额的历史快照。

### 年度奖金、绩效奖金和年终奖怎么填？

“年度奖金”是合计，绩效与年终奖是可选明细。填写合计时优先使用合计，只计入年包一次；合计留空时，仅汇总已填明细。

两项明细都填时需与合计一致，仅填一项时不能超过合计。未填表示未知，`0` 表示确认没有。旧合计不会被自动拆分。如果年终奖已算进“一年薪数”，不要再次记录为奖金。

### 年包是税后到手收入吗？

不是。常态年包是根据所填工资、奖金、股票、补贴等计算的税前估算，不含签字费；首年总包另计签字费。奖金和股票不是保证到账的收入，公积金和福利说明也不当作可支配现金。

### 城市生活里的收入和房价从哪里来？

由你填写。它不提供实时物价、房价、税务计算、自动汇率或贷款方案。税后现金需要自己确认；五项支出按月填写，空白不会当作零。

“安家还有多远”只是目标总价与已有资金的静态缺口试算，不包含未来涨跌、投资收益、交易税费或贷款利息。

### CSV 为什么只有一部分数据？

“Offer 对比 → 全部数据”的“导出本页 CSV”和“复制本页表格”只处理当前可见页，每页最多 50 条，不是导出全部匹配记录。需要其他页时请翻页分别导出；需要完整备份时请使用 JSON。

## 备份、隐私与 AI

### 有自动备份，还需要手动导出吗？

需要。自动备份也在这台电脑，按当月日号使用 `auto-01` 至 `auto-31` 槽位轮换，同日会更新对应槽位，不是永久历史档案。硬盘故障或整机丢失时，本机备份也可能一起丢失。

请查看最近成功备份时间，并定期手动导出 JSON 到自己选择的安全位置。

### JSON 备份里有附件和密钥吗？

没有附件文件本身，也没有 API Key。附件只保留路径，换电脑后需另行迁移文件并重新选择失效路径；密钥需在新电脑重新配置。未提交草稿和显示偏好也不属于 JSON 求职备份。

JSON 包含已保存的私人求职资料，请妥善保管，不能当作脱敏反馈文件发送。

### 导入会直接覆盖本机数据吗？

会先展示预览，按记录 ID 合并。冲突默认保留本机，只有明确勾选才覆盖；确认导入前会建立恢复快照，快照失败则不执行导入。

如果需要撤回，可以导入相应的导入前快照并检查冲突。但合并导入不会自动删除此前新增的记录，因此不是一键完整回滚。旧备份没有新版 PK / 预算资料时，不会清空本机已有方案。

### AI 免费吗？取消后还可能收费吗？

“免费 AI 起步”预设 OpenRouter 免费模型路由和 Tavily 搜索，需要你自己的两把密钥，不含共享额度或作者的 Key。免费服务可能限流或不可用，搜索账户也可能启用了付费计划；请在服务商控制台确认额度与计费。应用不会静默切换收费模型，但不能替你关闭服务商按量付费。

连接测试、AI 一键检查、招聘原文提取、手动调研，以及明确开启后的创建岗位自动调研，都会访问对应服务并可能消耗额度。自动调研默认关闭，没有后台定时调研。[完整配置与费用说明](AI-SETUP.md)

取消进行中的请求后，应用不会继续兜底调用或自动采纳结果，但不能保证服务商退还已经处理部分的费用。

### AI 报错或者没查到资料，怎么办？

先看 AI 设置顶部显示的“分析模型”“联网来源”和缺少的配置，再用“AI 一键检查”核对已保存的岗位路线，或分别测试模型与搜索。普通兼容模型和本机 Ollama 联网调研需要 Tavily；仅保存模型或模型连接成功，不代表已选择它执行任务，也不代表搜索可用。只使用原文提取不需要搜索服务。

没有主动改变使用范围的旧用户继续使用原策略：公司综合调研百炼优先，失败后可使用标明非联网的 DeepSeek 分析；岗位和风险调研使用 DeepSeek 官方联网接口。已选择新配置的任务按新配置执行，失败不会悄悄回到旧提供商或换成收费模型。

公开网站可能无法读取，模型结果也可能不完整。保留人工资料、手动补充即可，不要为排错公开密钥；AI 预览不会自动覆盖人工资料。更多传输边界见 [数据与隐私](PRIVACY.md)。

### 招聘页打不开，可以直接复制文字吗？

可以。在岗位详情选择“粘贴招聘原文”，先删除个人或敏感内容、核对岗位模型并同意费用，再提取。只调用模型，不搜索、不打开原文中的网址；所有建议默认不选，主动勾选后加入草稿，再明确保存。没有原文证据的字段不补猜，也不会生成公司共享资料或风险结论。[原文提取步骤](AI-SETUP.md#新方式粘贴招聘原文)

它不等于联网核实。云端模型会收到你粘贴的文字；全文只在窗口内存中保留，但已采纳字段和有限证据摘录可以进入草稿，正式保存后可进入记录及备份。

### AI 一键检查通过，就保证每次都能调研成功吗？

不保证。它只检查当前已保存的岗位联网路线，使用固定测试文字，不读取你的求职记录；最多一次模型测试加一次搜索测试，失败停止，可取消，不自动换服务。通过不代表真实招聘网页可读取、同名公司已经区分清楚、资料准确或额度一直充足。仅提取原文时，可以在模型卡单独测试模型，无需补配搜索。

### 能不能配置任意 AI 模型？

可以保存多套 **OpenAI 兼容 Chat Completions、Responses 或本机 Ollama** 配置，但不是“填任意品牌名就能用”。地址、协议、准确模型名及结构化输出能力都需匹配。只有网页版聊天账号不等于已经拥有 API 服务。使用自定义云端服务前，请确认其可信度和隐私政策。[自定义模型步骤](AI-SETUP.md#4-配置自己的模型)

### 只输入公司和岗位，为什么没有自动补全？

默认关闭自动调研。配置齐全后，在 AI 设置顶部勾选“创建岗位后自动调研”，点击“保存自动调研偏好”，之后新建成功的岗位才会自动调研一次。输入过程中、开启开关当下、普通重开旧岗位时都不会自动发起。旧岗位可直接点击详情中的“开始联网补全”。

### AI 已填进表单，关闭建议会撤销吗？

不会。“关闭建议（保留草稿）”只关闭预览，已填入的草稿还在；需要撤销时请用“AI 预填”区域的撤销功能，后来手动修改的内容会保留。点击“保存全部更改”才正式保存；不确定的建议先打开来源核实。

### 数据“保存在本机”，是不是全部加密？

不是。API Key 使用 Windows 安全存储加密，普通记录、草稿和导出备份不能视为加密保险箱。请做好电脑账户与备份文件的访问保护，不要在备注里保存密钥。

## 项目与反馈

### 这是开源项目吗？可以在这里找应用源码吗？

不是。Offer King 是闭源软件，本仓库只提供发布文件、文档和反馈入口。软件使用范围见 [LICENSE](../LICENSE.md)，第三方组件遵循各自许可。

“闭源发布”表示不公开应用源代码，不等于承诺客户端程序无法被检查或逆向分析。

### 怎样反馈最有帮助？

使用 [问题反馈表](https://github.com/YCC-Lover/Offer-King/issues/new?template=bug_report.yml)，填写应用版本、Windows 版本、复现步骤、预期与实际结果。涉及显示问题时，也可以说明系统缩放比例、应用字号和主题。

Issues 公开可见。请遮住个人信息，不要上传完整备份、密钥、私人附件或原始数据目录。应用内“帮助与关于”可以导出脱敏诊断，发送前请自行复查。功能想法和教程问题也都欢迎，[选择合适的反馈类型即可](https://github.com/YCC-Lover/Offer-King/issues/new/choose)。
